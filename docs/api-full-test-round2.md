## 结论与教训

1. **"改完 lunar-common 必须重启所有服务"**：本轮三次失败里有两次的根因都是"服务跑着旧 jar"。这已经写进流程：任何 lunar-common 变更后，先全量重启再做验证。
2. **失败要取原始证据再定性**：第一轮我看到"空 401 / 500"就判成产品缺陷，实际是部署状态问题；第二轮看到 404 就判成回归，实际是新契约生效。两次都是**先取响应体/响应头**才定位准的。
3. 测试脚本本身也是代码：它需要跟随契约演进（本轮补了"加入题目并锁定版本"这一步）。
