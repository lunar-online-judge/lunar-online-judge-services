# 考试业务流程（当前确认版）

本文档记录目前已经确认的考试规则。仍存在冲突或尚未回答的规则，统一放在“待确认决策”中，不应在代码中自行假设。

> **实现现状提示（2026-10）**：本文档记录的是"已确认的规则"，**不等于"已实现"**。当前尚未落地的确认项包括：随机题目分配（§3）、进入考试的客户端版本/屏幕采集/网络/摄像头预检与四种降级处置（§5）、"同一账号仅一个活动客户端会话 + 踢旧设备 + 重复登录告警"（§6）、按测试点通过比例的部分分与"该题最高有效分"（§7）、成绩状态机 `PROVISIONAL → UNDER_REVIEW → FINAL/REVOKED`（§7）、指定题目公告（§8）、CSV 批量导入（§9）。§10 的 6 项待确认决策，代码没有做任何假设。逐项现状见 `docs/services.md` 各服务"当前实现/下一步"与 `docs/api.md` 端点总表。

## 1. 考试基本模型

考试和竞赛暂时使用同一个业务概念，统一由 `contest-service` 管理。考试主要面向统一时间窗口的编程题考试。

考试生命周期：

```text
DRAFT -> REVIEWING -> PUBLISHED -> RUNNING -> FINISHED -> ARCHIVED
```

- 老师可以创建和维护考试；
- 管理员审核并发布考试；
- 发布前需要校验题目、随机题库、语言、评分规则、学生名单、监考策略和时间窗口；
- 老师可以发布考试公告；
- 学生没有“交卷”操作，服务端以统一结束时间自动关闭考试入口；
- 考试结束后不能再次进入考试，也不能修改已经产生的评分。

## 2. 角色权限

当前权限规则：

| 角色 | 权限 |
|---|---|
| 老师 | 添加/管理学生账号、创建考试、选择题目或题库、设置评分规则、发布公告、查看源码/评测结果/风险事件/截图/实时屏幕/摄像头 |
| 管理员 | 拥有老师全部权限，并可以创建老师账号和管理员账号 |
| 考生 | 登录、进入被分配考试、查看题目、提交代码、查看评测结果 |
| 监考员 | 按考试授权查看实时监考信息和处理风险告警 |

当前决定是所有老师都可以管理学生账号。考试级数据和媒体访问仍必须写入审计日志；管理员和老师的高风险操作必须记录操作者、时间、目标考试、目标学生和操作结果。

## 3. 题目选择和随机分配

老师可以：

- 手动选择题目；
- 从题库选择题目；
- 配置每位学生随机抽取的题目数量；
- 配置题目顺序、分值和评分规则。

默认规则是：

```text
老师选择题目/题库
        ↓
考试发布时生成随机分配结果
        ↓
每位学生获得相同数量的随机题目
        ↓
学生进入考试后使用已生成的题目集合
```

题目分配至少需要保存 `contestId`、`studentId`、`problemVersionId`、`randomSeed`、`assignedAt` 和分配版本，保证考试后可以复现学生看到的题目。

代码查重默认：

- 相同题目的提交进行主查重；
- 不同题目的高相似度只能作为辅助风险证据；
- 查重结果不自动取消成绩。

## 4. 考试时间

- 所有学生统一开始、统一结束；
- 考试开始后迟到学生可以进入，但不补偿迟到时间；
- 服务端以服务器时间判断是否允许进入和提交；
- 考试结束后禁止新提交；
- 学生没有主动交卷接口；
- 时间结束后学生不能进入考试，也不能修改评分。

老师发布公告不会自动延长考试时间。考试时间调整规则仍待确认，当前只能由后端保留调整记录和审计能力。

## 5. 进入考试预检

当前预检项目：

- 账号有效；
- 学生在考试名单中；
- 客户端版本；
- 屏幕采集能力；
- 网络连接；
- 摄像头设备状态。

当前处理规则：

| 预检结果 | 处理 |
|---|---|
| 账号或名单校验失败 | 禁止进入 |
| 屏幕采集失败 | 允许进入，但立即产生高风险告警 |
| 网络失败 | 允许进入，但立即产生高风险告警 |
| 客户端版本不符合 | 允许进入，但限制提交能力，并要求升级 |
| 没有摄像头 | 记录 `CAMERA_MISSING`（词表见 `RiskRules`），不报警 |

考试中屏幕采集恢复、持续失败、提交限制和监考员人工处理的最终阈值仍待确认。

## 6. 登录和断线

登录接口自带失败限流，同一账号连续失败触发短暂锁定（约束见 `docs/architecture.md` §2.1.2）；登录、令牌签发由 auth-service 负责，接口约定见 `docs/api.md`。

同一学生账号只能保持一个活动客户端会话：

```text
新客户端登录
      ↓
旧客户端会话失效
      ↓
旧客户端产生被踢下线事件
      ↓
管理端产生重复登录告警
```

客户端断线或崩溃后可以重新登录，保留考试会话和剩余时间；重启、断流、恢复时间都写入风险事件，但不自动判定作弊，也不自动补时。

## 7. 提交、评分和实时结果

学生完成某道题后提交代码，评测完成后立即看到结果和得分。学生可以无限次提交，但服务端仍会做频率限制和反滥用控制。提交前置校验（会话有效、竞赛进行中、题目属于竞赛、语言允许、次数未超限）、幂等与事件链路见 `docs/architecture.md` 第 8 节和 `docs/api.md`。

同一道题多次提交时：

- 每次提交和评测结果都保留；
- 临时成绩取该题最高有效分；
- 页面可以同时显示最高分和最近一次提交状态；
- 查重和风控使用完整提交历史。

评分规则当前确认支持：

- 通过全部测试点得满分，否则 0 分；
- 按测试点通过比例给部分分；
- 暂不实现测试点独立权重和自定义 checker。

考试结束后成绩状态采用：

```text
PROVISIONAL -> UNDER_REVIEW -> FINAL
                         \-> REVOKED
```

当前无学生申诉流程。风险确认后的处罚操作仍必须保留人工审核和审计记录。

## 8. 公告

老师可以发布：

- 考试全体公告；
- 指定题目公告；
- 重要公告；
- 需要学生确认的公告。

公告至少保存发布人、发布时间、目标范围、正文、是否需要确认、送达时间和确认时间。公告默认不改变考试时间。

## 9. 学生账号和名单

老师可以逐个添加学生，也可以使用 CSV 批量导入。建议字段：

```text
studentNo,username,displayName,initialPassword
```

CSV 每一行等价于一次"添加学生"调用：逐行携带 `Idempotency-Key`，复用相同的唯一性校验和审计；部分行失败不回滚已成功行，响应中逐行返回成功或失败原因。

已存在账号可以由老师或管理员调整、绑定到考试。学生从考试名单移除时：

- 当前考试报名关系软删除；
- 当前考试会话失效；
- 学生账号保留；
- 其他考试、历史提交和评测结果不受影响。

## 10. 关键待确认决策

以下内容因当前答案之间存在冲突，暂不写入实现约束：

1. **考试结束后的评测任务**：此前选择过“已接收任务继续评测”，也选择过“立即终止所有评测”，需要最终二选一；
2. **考试开始后修改题目**：已选择允许修改，但需要明确是否允许修改题面、测试数据、分值和随机题库；
3. **随机公平约束**：目前只确认相同题目数量，难度、知识点、总分平衡和随机池最小规模尚未确认；
4. **重复登录后的恢复**：当前确认踢出旧设备并告警，但旧设备能否重新登录尚未确认；
5. **管理员最终发布成绩**：已确认管理员拥有老师全部权限，但老师初审、管理员最终发布的具体顺序尚未确认；
6. **考试结束后的成绩可见范围**：目前确定由考试配置控制，具体配置项尚需落表。
